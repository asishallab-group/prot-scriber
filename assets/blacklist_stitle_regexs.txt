# A sequence title matching any of these is discarded whole: it carries no description at all, so
# there is nothing in it to score. Compare filter_stitle_regexs.txt, which deletes PART of a title.
#
# FORMAT. One expression per line and nothing else -- no replacements, no continuation: an
# expression never spans lines. A line whose first non-blank character is '#' is a comment,
# and a blank line is nothing. An expression may still match a literal '#'; write it as
# '[#]', which no regex dialect can read as anything else.

# A title saying only that the protein resembles something, or is a guess.
(?i)\bsimilar\s+to
(?i)\bprobable\b
(?i)\bputative\b
(?i)\bpredicted\b
(?i)\buncharacterized\b
(?i)\bunknown\b
(?i)\bhypothetical\b
(?i)\bunnamed\b

# A title describing the state of the sequence rather than the protein.
(?i)\bfragment\b
(?i)\bwhole\s+genome\s+shotgun\s+sequence\b
(?i)\bclone\b

# A title that is nothing but an accession or a locus code -- 'CAN6812812.1', 'WP_485061005.1',
# 'At3g47570', 'ZYRO0A01628g', 'AO090001000135'. An entry with no description at all has one of
# these and nothing else, and without this rule the code's letters become a word: the filter
# lists' accession rule needs whitespace AFTER the first token, so it never fires, and the
# capture-replace pairs then rewrite 'can6812812.1' to 'can'.
#
# A RUN of four or more digits is what separates such a code from a gene name, and it is the run
# that matters and not where it sits: an earlier version required the digits to come last, which
# let through every systematic name with a letter after them -- 196 distinct ones in Swiss-Prot,
# and 'At3g47570' too, the very code the rule was written for. TP53, IL6, SH3, SLC25A24 and
# C18orf32 have no run of four and so are left alone, and the anchors keep a code that is only
# PART of a description ('Transposon Tn1545 resolvase') out of it.
(?i)^\s*[a-z][a-z0-9_.]*\d{4,}[a-z0-9_.]*\s*$
